# Essential Design Patterns for AI Systems – Revision Notes

## 1. Overview

This lesson introduces **three core LLM workflow design patterns** used when building AI systems:

1. **Sequential Pattern (Prompt Chaining)**
2. **Routing Pattern**
3. **Parallelization Pattern**

These patterns are implemented using **LangGraph**, which structures workflows using:

- **State variables** → store data during execution  
- **Nodes** → represent agents or LLM operations  
- **Edges** → define execution flow between nodes  

---

# 2. Sequential Pattern (Prompt Chaining)

## Definition
The **Sequential Pattern** passes the output of one LLM directly as input to another LLM.

This breaks complex tasks into **smaller specialized steps**.

---

## Example Scenario

Task: **Generate a cover letter**

Workflow:

1. **Agent 1** – Resume expert
   - Reads job description
   - Creates a resume summary

2. **Agent 2** – Professional writer
   - Uses resume summary
   - Generates cover letter

Workflow:

```

Job Description
↓
Resume Summary Agent
↓
Cover Letter Agent
↓
Final Cover Letter

```

---

## State Variables

| Variable | Purpose |
|---|---|
| job_description | Input job description |
| resume_summary | Summary generated by first agent |
| cover_letter | Final generated cover letter |

---

## Workflow Steps

### 1. Initialize Environment
- Import libraries
- Initialize LLM

---

### 2. Define First Node

**generate_resume_summary**

Function:
- Reads job_description
- Creates prompt
- Calls LLM
- Stores result in `resume_summary`

---

### 3. Define Second Node

**generate_cover_letter**

Function:
- Uses `resume_summary`
- Uses `job_description`
- Generates cover letter
- Stores result in `cover_letter`

---

### 4. Build Graph

Steps:

1. Create graph with state
2. Add resume summary node
3. Add cover letter node
4. Connect nodes sequentially
5. Set entry and end nodes
6. Compile workflow

---

## Advantages

- Simple workflow
- Easy to understand
- Ideal for multi-step tasks

---

# 3. Routing Pattern

## Definition

The **Routing Pattern** selects the correct agent based on user input.

A **router agent** analyzes the request and decides which node should process it.

---

## Example Scenario

User input may require:

- **Summarization**
- **Translation**

Workflow:

```

User Input
↓
Router Agent
↓     ↓
Summarize   Translate
↓         ↓
Final Output

```

---

## Router State Variables

| Variable | Purpose |
|---|---|
| input | User query |
| task_type | Determined task (summarize / translate) |
| output | Final result |

---

## Implementation Steps

### 1. Create Router Schema

Use **Pydantic schema** so the LLM outputs either:

- `summarize`
- `translate`

---

### 2. Router Node

Function:

1. Read user input
2. Send prompt to LLM
3. Determine task type
4. Store result in `task_type`

---

### 3. Conditional Routing

Based on `task_type`:

- If **summarize** → send to summarize node
- If **translate** → send to translate node

---

### 4. Summarize Node

Prompt:
```

Summarize the following text

```

Stores result in:

```

output

```

---

### 5. Translate Node

Prompt:
```

Translate the following text

```

Stores result in:

```

output

```

---

## Advantages

- Dynamic decision-making
- Efficient task handling
- Supports multiple workflows

---

# 4. Parallelization Pattern

## Definition

The **Parallelization Pattern** runs multiple LLM tasks **simultaneously**.

This increases:

- Speed
- Throughput
- Efficiency

---

## Analogy

Kitchen example:

- Chef 1 → chops vegetables
- Chef 2 → boils pasta
- Chef 3 → bakes bread
- Head chef → combines dishes

---

## AI Workflow Example

Translate text into multiple languages simultaneously.

```

English Text
↓
┌───────────────┐
↓      ↓      ↓
French  Spanish  Japanese
Translation Nodes
↓
Aggregator
↓
Combined Output

```

---

## State Variables

| Variable | Purpose |
|---|---|
| text | Original English text |
| french | French translation |
| spanish | Spanish translation |
| japanese | Japanese translation |
| combined_output | Merged result |

---

## Workflow Steps

### 1. Define Translation Nodes

Each node:

- Receives `text`
- Generates translation
- Stores result

Example:

```

translate_to_french
translate_to_spanish
translate_to_japanese

```

---

### 2. Parallel Execution

All translation nodes start **simultaneously**.

Edges:

```

Start → French
Start → Spanish
Start → Japanese

```

---

### 3. Aggregator Node

Function:

- Collect all translations
- Merge results
- Store in `combined_output`

---

### 4. End Node

Graph execution completes.

---

## Advantages

- Faster execution
- Handles independent tasks
- Improves scalability

---

# 5. Design Pattern Comparison

| Pattern | Description | Best Use Case |
|---|---|---|
| Sequential | LLM outputs passed step-by-step | Multi-step workflows |
| Routing | Router selects appropriate agent | Dynamic task selection |
| Parallelization | Tasks executed simultaneously | Independent operations |

---

# 6. LangGraph Workflow Components

## State Variables
Store data throughout the workflow.

Examples:
- input text
- intermediate results
- final outputs

---

## Nodes
Represent **LLM operations or agents**.

Examples:
- summarization
- translation
- evaluation

---

## Edges
Define **execution flow** between nodes.

Types:

- Sequential edges
- Conditional edges
- Parallel edges

---

# 7. Key Takeaways

- **Sequential Pattern**
  - Chains LLM outputs step-by-step.

- **Routing Pattern**
  - Router agent directs tasks to the correct node.

- **Parallelization Pattern**
  - Multiple LLM tasks run simultaneously.

- **LangGraph** enables structured workflows using:
  - state variables
  - nodes
  - directed edges

These patterns are essential for building **scalable AI agent systems**.
